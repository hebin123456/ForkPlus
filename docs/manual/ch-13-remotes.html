第 13 章 · 远程交互

ForkPlus 用户手册 · 版本 v5.0.6

总览 分支操作 标签操作 历史改写 Stash 贮藏 远程交互 合并冲突解决 子模块与 Worktree 补丁与快照

Fetch 拉取

「Fetch」对话框用于从远程获取更新而不合并。默认仅针对当前活动的上游，也可以下拉选择其他远程。对话框底部实时预览将要执行的 git fetch 命令。

Fetch 全部远程

勾选「所有远程」开关后，将一次性从配置的全部远程拉取，并把 FETCH 命令扩展为遍历每个远程的完整形式，适合远程较多时一键同步引用。

Pull 合并拉取

「Pull」对话框把远程更新合并到当前分支。默认采用 git pull 的快速合并语义，也有回退到 Rebase 的选项。命令预览会随选择切换。

提交预览（v4.2.1）：当拉取会带入新提交时，对话框会列出「将合并进来的提交」。该预览区（与 Push 强推覆盖预览、Reset 丢失提交预览共用一套呈现）折叠头与摘要行同左缘、SHA 与提交说明同行对齐，列表限高滚动、窗口不被撑高；预览行的短 SHA 是超链接，点击可直接打开该提交的变更详情面板。

Pull 并 Rebase

勾选「以 Rebase 方式拉取」，Pull 将改为 git pull --rebase，把本地提交重新摆放到远程最新提交之上，形成更线性的历史。

Push 推送

「Push」对话框把本地分支推送到远程。对于已建立上游的分支，窗口会预填远端与命令预览；你还可以勾选是否同时推送所有标签。

提交预览（v4.2.1）：强推覆盖远程时同样会列出「将被覆盖的提交」，呈现与拉取预览一致——折叠头左对齐、SHA 与提交说明同行对齐、列表限高滚动；预览行的短 SHA 是超链接，点击可直接打开该提交的变更详情面板。

编辑远程：添加

「编辑远程」对话框以 Add 模式添加新的远程：输入名称与 URL 后，预览 git remote add 命令，用于注册新的远程源。

编辑远程：修改

选择已存在的远程后进入 Edit 模式，自动预填原名称与 URL，修改后预览 git remote set-url 命令，便于更新远程地址而不丢失本地跟踪关系。

自定义 Refspec

「添加自定义 refspec」对话框允许为某个远程补充额外的 fetch 映射规则，以自定义的 refspec 精确控制从远程获取哪些引用，适合特殊的分支/标签同步需求。

推送新分支到远程

当本地分支尚未建立上游时，Push 对话框会以「推送新分支」呈现：选择目标远程后，预览以 --set-upstream 建立跟踪关系的推送命令，让后续 Push/Pull 文件名自动关联。

删除远端

「删除远端」对话框用于删除不再需要的远程仓库：选中某个远程后，会显示将要执行的 git remote remove <name> 命令预览，确认后删除该远程及其所有引用（本地对它的 origin/<branch> 引用一并移除）。删除前请确认本地没有依赖该远程的尚未推送的分支。

v4.3.0 修复：此前该弹窗的 logo 图标与标题 / 说明文字、内容与命令预览相互重叠（根容器缺少行定义、图标列宽取值错误），现已按通用弹窗布局规范重排为「图标列 + 标题行 + 内容行」；同时移除了一个与基类成员重名、实际不参与布局的死控件。功能与文案未变。

变更远程跟踪

「变更远程跟踪」对话框用于调整本地分支与其上游远程分支的关联关系：可为当前分支选择新的上游（预览 git branch --set-upstream-to 命令），或取消跟踪（预览 git branch --unset-upstream）。当分支不再跟踪远程、或需要把跟踪目标切换到另一个远程分支（如接管他人分支）时使用。

说明：远程相关操作完成后，仓库的远程分支列表（origin/<branch>）会自动刷新。若本地与远程分叉，可结合「历史改写」章节的 Rebase/Fetch 选择适合的同步策略。

分支下拉框搜索（v4.2.0）

当仓库分支较多时，在下拉列表里逐个翻找目标分支很费时。v4.2.0 起，凡是从列表中选择分支的下拉框都内置了搜索过滤：打开下拉后，顶部会出现一个搜索框并自动获得焦点，输入关键字即可即时过滤出匹配的分支（按项名称做不区分大小写的包含匹配），直接点选结果即可。适用于 Push（本地 / 远程分支）、Pull、变更远程跟踪、创建 Worktree、GitFlow 各窗口的分支下拉框，以及提交历史顶部的 Ref 选择器。

小贴士：下拉打开后直接键入即可过滤，无需先点击搜索框。键盘操作：↑/↓ 在可见结果间移动选中，Enter 选中并关闭下拉，Esc 先清空搜索词、再关闭下拉。关闭下拉后列表与原有选中项会原样恢复。
